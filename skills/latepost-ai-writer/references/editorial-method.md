## 核心不是腔调，而是报道结构

这批语料的共同方法可以概括为：

1. 用一个具体变化打开文章。
2. 迅速建立变化发生前的基线。
3. 找到变化背后的组织、技术、资本或权力矛盾。
4. 用数字、人物动作、时间线和对手比较验证判断。
5. 把结论停在下一阶段最难解决的约束上。

“像晚点”不等于多写破折号、引号或金句。最重要的是信息顺序、事实密度和对矛盾的克制判断。

新增批次强化了一个共同点：报道不满足于“公司宣布做什么”，而是继续追问能力处在哪一阶段、钱以什么口径存在，以及组织动作是否产生了产品和客户结果。

## 标题

### 常见结构

- 人物或公司 + 关键变化：突出谁正在改变什么。
- 事实 + 后果：用数字、融资、人事或产品节点兑现新闻价值。
- 路径 + 矛盾：呈现“做对了什么，但仍卡在哪里”。
- 引语或非共识 + 对象：只在正文能够完整解释时使用。
- 从 A 到 B：用于真实路径变化，不作为装饰。
- 多议题并列：只用于月报，每个分句都必须代表一个可展开的趋势判断。

标题中冒号、数字、引号和反差都很常见，但它们服务于双层信息：前半给对象或事实，后半给判断或张力。

### 检查

- 标题中的每个强判断能否在正文找到至少两类证据？
- 数字是否有时间、口径和来源？
- 标题是否把“公司希望成为”误写成“公司已经成为”？
- 删除栏目名和修辞后，新闻事实是否仍然成立？

## 导语

导语不是摘要清单，而是一条逐步收紧的路径：

1. 第一段给动作、时间、场景或决定性事实。
2. 第二段说明这件事为什么异常。
3. 接着用历史对比或竞争状态建立基线。
4. 再揭示矛盾：新策略解决了什么，又制造了什么。
5. 最后把读者带入全文的核心问题。

组织深描 3641 先写年轻负责人进入腾讯，再把个体动作提升为“大公司如何重建秩序”的问题。事件稿 3448 先列离职后的连续动作，再解释制度冲突。快讯 3540 则先给融资额、估值和投资方，随后用历史融资和收入数据建立意义。

新增语料中，2904 用 2330 名研究者建立人才竞争基线，再进入三家公司不同的组织形态；3017 用供应链盯梢和工厂现场进入机器人泡沫，随后以订单、成本和人工装配拆解“量产”叙事；3658 则直接把“最成功”和“最危险”并置，定义 AI 应用公司的生存矛盾。

避免：

- 从“随着 AI 快速发展”开始。
- 用三段行业常识拖延新闻事实。
- 第一段堆五个概念，却没有人物、动作或数字。
- 导语承诺一个产业问题，正文却只写公司宣传材料。

## 正文推进

### 按问题组织，而不是按资料来源组织

同一采访、财报和公开资料应被拆进不同章节。每节回答一个问题：

- 为什么现在发生？
- 过去哪里失效？
- 新方案具体改了什么？
- 对手为什么可能更强？
- 资源、组织或商业化瓶颈是什么？

### 使用递进结构

常见的长稿弧线：

- 变化 → 诊断 → 重建 → 外部竞争 → 未决约束
- 产品结果 → 技术机制 → 成本与资源 → 商业化
- 人物路径 → 非共识判断 → 现实验证 → 长期动机
- 市场现象 → 多方策略 → 共同瓶颈 → 权力重分配
- 多个当期事件 → 共同机制 → 公司与市场后果 → 哪个判断发生变化
- 具体事故/研究 → 概念机制 → 相反证据 → 人与制度的选择

3641 的章节从旧问题诊断推进到组织重建，再走向业务协作与信任约束。3393 用相同维度比较字节、阿里和腾讯，使公司差异变成一场可比较的战争，而不是三段公司简介。

### 段落

- 每段只有一个主要信息单元。
- 判断后尽快给事实；事实后说明它改变了什么。
- 背景只保留理解当前矛盾所需的部分。
- 转折必须改变读者判断，不要用“值得注意的是”承接无关信息。
- 小标题表达动作、变化或争论，不用“发展历程”“未来展望”。

## 证据与信源

### 证据层级

1. 可复核原始材料：公告、财报、产品记录、论文、测试日志。
2. 具名当事人或直接参与者。
3. 有明确身份边界的匿名来源。
4. 行业分析与二手报道。
5. 作者推断。

越靠后越需要明确归因，不能伪装成确定事实。

### 数字

数字不是装饰，应至少完成一项功能：

- 定义变化规模。
- 与过去或对手比较。
- 揭示成本、速度或资源约束。
- 证伪公司叙事。

给数字配齐时间、单位、口径和来源。无法比较的数字不要制造虚假精确。

### 匿名信源

匿名来源的身份描述只保留理解其信息权限所需的粒度。不要把“一位员工”升级成“接近高层人士”，不要把单一来源写成行业共识。匿名信息与公开材料冲突时，显式说明冲突并降低结论强度。

## 商业化与能力阶段

### 不跨级写结论

AI 报道最常见的证据错误，是把相邻阶段写成同一件事。写作前先标注：

- 能力：演示 → 内部基准 → 公开评测 → 受控实测 → 真实用户稳定使用。
- 落地：意向 → 试点 → 部署 → 付费 → 复购 → 规模化。
- 收入：融资 → 估值 → 合同额 → 回款 → 确认收入 → ARR。

每个阶段只能证明本阶段。演示视频证明“做出过”，不证明无人介入；客户名单不证明付费；合同额不等于收入；ARR 需要说明计算时点和经常性。

### 不让组织信号替代结果

组织和人才报道至少回答三层：

1. 谁加入、离开或改变汇报关系。
2. 预算、算力、研究方向和产品节奏怎样变化。
3. 模型、产品、客户或收入是否出现可验证结果。

2904 以公开论文数据库、履历和人员流动比较大厂研究组织；2891 将独立组织与全链条投入连接；2897 则解释学术循环为什么能转化为模型迭代。三者共同说明，人才是过程证据，不是胜负结论。

### 具身与智驾的现实刻度

对机器人和智驾分别记录场景、硬件、数据来源、人工接管、失败条件、安全责任、成本和交付规模。3017 把几千套订单、手工装配和工人成本并列；2939 区分功能能力与宣传口径；2691 用事故、停运和信任损失说明规模不是唯一约束。

## 技术解释

每个技术概念按四步处理：

1. 用一句普通语言说明它要解决的问题。
2. 与旧方案比较核心差异。
3. 给一个具体任务、产品或成本例子。
4. 说明代价、边界和受影响者。

3216 不是罗列 Agent 工具，而是围绕“如何把模型能力变成可用工作流”组织玩家与工具。3278 先说明公开榜单与日常体验的差距，再给测试范围、限制和真实任务，使结论可复核。

Agent 与 AI 应用还要检查工具权限、上下文来源、人工确认、失败恢复和单次任务成本。2898 的核心不是 Agent 产品数量，而是“开发容易、持续好用难”；2932 从工作场景和系统组成解释产品路线，适合用来校验机制与实际任务是否相连。

避免：

- 把参数规模或榜单名次直接等同于产品能力。
- 只解释机制，不解释成本和失败条件。
- 把公司路线描述成行业终局。
- 用类比替代机制，或让类比比概念更难懂。

## 人物与引语

人物不是履历表。选择能解释其判断形成过程的经历，并把经历连接到当前选择。

人物稿或访谈导语通常回答：

- 这个人现在做成了什么？
- 他选择了哪条非主流路径？
- 这条路径来自什么经历？
- 市场为什么会质疑？
- 访谈最值得验证的判断是什么？

3644 从音乐学习经历进入工具创业，再用收入、用户和融资证明人物不是只讲愿景。3645 把大厂研究院兴衰与创业选择连起来，使技术路线与人物动机相互解释。

AI 创业访谈还应主动拆开 PMF、增长和商业化。3658 用“模型能力与用户需求之间的空缺”解释机会与危险；3078 先定义产品要替用户完成什么，再追问数据、收费与身份风险；3025 用产品效率、融资和创始人经历建立访谈价值。创始人的愿景必须由指标、反例或成本约束。

引语只在以下情况保留：

- 它提供无法替代的一手事实。
- 它准确暴露冲突或立场。
- 它展示人物的思考方式。
- 它形成有证据支撑的结尾。

其余内容用准确转述提高密度。

## 新增稿型的方法

### AI 月报与趋势综合

月报不是把新闻按日期缩写。先选 2–4 个改变判断的议题，每节依次写：

1. 本月发生了什么。
2. 多个事件背后的共同机制是什么。
3. 它改变了哪些公司的资源、产品或市场位置。
4. 哪个反例使结论仍不能确定。

2898 从 Agent 的复刻速度进入真实可用性；2966 把模型、用户和算力投资分别作为趋势问题；3103 用复盘式对话检验半年度判断。投融资信息单列时，也要说明资本热度与收入需求不是同一指标。

### AI 创业访谈

采用“叙事前言 + 追问式问答”：

- 前言用产品、用户、收入、融资或失败证明采访价值。
- 第一组问题验证用户问题和 PMF。
- 第二组验证技术与产品选择。
- 第三组追问获客、留存、定价、交付与收入口径。
- 最后一组回到竞争、模型挤压和创始人为什么仍下注。

不要让前言替受访者提前赢得争论。强判断旁至少放一个可复核指标或反例。

### AI 议题观察

从事故、实验或人的具体处境起笔，再解释技术概念。3086 区分模型欺骗现象、研究者解释与价值判断；2947 从技术焦虑进入人的主体性；2894 将事故、能力边界、宣传和责任放进同一问题。此类稿件尤其需要标注研究样本、争议和作者推论，避免从个案直接跃迁到“人类命运”。

## 结尾

结尾通常不总结全文，而是重新定义文章开始时的问题：

- 新策略有效，但下一阶段依赖更难获得的资源。
- 技术已被证明可行，但商业化和组织仍未被证明。
- 人物有清晰判断，但市场窗口或竞争对手不会等待。
- 一次产品体验展示可能性，也暴露权限、生态或成本瓶颈。

3648 最后把手机 Agent 的技术问题落到平台之间的权力关系。3540 从融资回到算力、成本和产品溢价，说明钱是必要条件而非答案。3291 用真实测试结果说明新的交互可能已出现，但生态权限仍是主要约束。

3017 最后把机器人硬件难题与自动驾驶问题并置，仍落在产业现实；2904 从人才竞赛回到大公司的组织惯性；3658 让创始人的回答停在“如何不被模型进化丢下”的不确定性。好的结尾缩小确定性，而不是放大口号。

避免：

- 重复导语与小标题。
- 突然拔高到人类命运。
- 用口号替代未解决的问题。
- 为了漂亮而写没有证据的金句。
