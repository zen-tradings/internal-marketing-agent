## 发布状态与故障处理

`remote_operations` 的 `prepared` 表示请求尚未开始；发送前持久化为 `attempting`。有可靠远端 ID 后为 `confirmed`；明确拒绝为 `rejected`；连接断开等不确定结果经过回查仍不能确认时为 `needs_review`。只有明确拒绝允许以后重新尝试；未知结果不自动创建第二份内容。Discord 没有可用的无 ID 查询接口，未知 POST 结果直接待人工核对。

普通发布不再位于内容生成重试循环内。启动时，已保存 `media_id` 的运行中任务恢复为成功并补全成功通知；已尝试发布却没有最终确认的普通任务进入 `needs_review`，不参与直译自动续跑。未尝试发布的直译仍可从 checkpoint 继续。

正式 Opening Digest 在第一次写 Customer.io 前保存邮件和派生内容。成功/排期确认、任务 `done`、派生 outbox 和成功通知一次事务提交。中途退出后使用冻结内容恢复；派生渠道失败或待核对保持邮件任务 `done`。人工 TEST 继续不进入 Discord。

`needs_review` 是明确的人工处理终态，不是自动重试队列。先核对平台上的内容与操作记录，不得手改 SQLite 状态或重新提交同一发送任务来绕过保护。现有受限恢复命令保持原范围，不接受该状态。缺少远端可核验证据时，保留该状态是“优先避免重复”的预期行为。

## 数据库、单实例与回滚

实例锁绑定真实数据库路径，使用独立 SQLite 连接持有操作系统锁；不阻止对业务数据库的只读健康/备份查询。锁在数据库旁，兼容 systemd `PrivateTmp`。进程退出释放锁，残留锁文件无需清理；删除该文件会破坏互斥，不允许这样解锁。数据库硬链接被拒绝；仅支持单机本地 SQLite 文件。

迁移版本 1 记录历史基线，版本 2 增加冻结意图和操作 payload。迁移在事务内完成，保留历史数据和列。旧版本可读旧列，但其重试语义不安全：回滚必须停服务后通过新版本的 `check:rollback`。未完成发布、补发或通知会阻止旧服务自动启动；不要恢复旧数据库来消除这些记录。
